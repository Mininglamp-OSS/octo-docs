The **Marketplace** is Octo's control plane for discovering and distributing
[Agent capabilities](/concepts/the-agent-model). The standalone
[`octo-marketplace`](https://github.com/Mininglamp-OSS/octo-marketplace) service
stores each catalog asset as a **plugin** with one of four types:

| Plugin type | Capability |
|---|---|
| `skill` | A packaged `SKILL.md` capability and its supporting files. |
| `connector` | A connection descriptor, including MCP server connections. |
| `expert` | An expert definition. |
| `expert_team` | An expert-team definition and its relationships. |

<Info>
  This page follows [octo-cli v0.19.5](https://github.com/Mininglamp-OSS/octo-cli/releases/tag/v0.19.5)
  and [Marketplace v0.8.0](https://github.com/Mininglamp-OSS/octo-marketplace/releases/tag/v0.8.0).
  The [generated CLI reference](/reference/octo-cli) is a separately pinned v0.18.0
  subset and does not enumerate Marketplace. A released contract does not establish
  which version or review policy your deployment runs.
</Info>

## Skill

A **Skill** is a reusable capability packaged around a root `SKILL.md`, with optional
supporting files. Your Agent runtime controls how it loads and uses the installed
capability. See [Build & publish a Skill](/guides/bot-developers/publish-a-skill)
for authoring.

The unified catalog adds discovery, version snapshots, and distribution:

| Stage | What happens |
|---|---|
| **Upload and parse** | Initialize an upload, PUT the archive using the returned upload instructions, then parse it and wait for the parse task to succeed. |
| **Import** | `plugin import` consumes the completed parse task. Creating a plugin saves a draft and a version snapshot; it does not publish it. Tenant writes accept `private` or `space`, not the retired `public` value. |
| **Publish or review** | An explicit publish follows the plugin's visibility and the Space's review policy. Private publication remains owner-only; Space publication may be immediate or require owner/admin approval. |
| **Update** | Published Space content must use a frozen review submission. Direct import/upsert edits are rejected; saving an editable plugin is not a substitute for publication. |
| **Download** | `plugin download` streams a ZIP reconstructed from the attachment tree. Use `--output` to save it; this is not the old `download_url` plus `file_sha256` JSON response. |

See [Publish to the Marketplace](/guides/integrators/marketplace) for the
save, publish, and review boundaries.

## MCP

An **MCP** connector describes a
[Model Context Protocol](https://modelcontextprotocol.io) server that an Agent runtime
can connect to. Discover it as `plugin_type=connector`; an MCP connection is one
connector subtype, not a separate catalog.

The connector package includes a root `mcp.json` containing its `mcpServers`
connection entries. Inspect the command or URL, transport, and required environment
variables or headers before adding an entry to your runtime. MCP connectors do not
use the Skill ZIP download flow.

<Warning>
  Keep consumer-supplied secrets as `${VAR}` placeholders in catalog documents.
  Do not upload real secrets. Supply real values only through the target runtime's
  approved secret mechanism.
  Do not assume catalog publication or a successful probe makes a connection safe
  to run, and do not rely on the old catalog's secret-redaction behavior.
</Warning>

`octo-cli marketplace mcp probe --data @connection.json` remains available for
`streamable-http` and `sse` connections. It makes a remote connection without
persisting the supplied configuration and returns connection information and tools.
Check the response's `is_ok` value; HTTP 200 alone does not establish probe success.
Do not send real secrets merely to validate a recipe. The Marketplace does not
launch `stdio` commands; validate those in the intended runtime.

## CLI

Use the unified plugin commands with CLI v0.19.5. Replace `PLUGIN_ID` with an
actual identifier before running the detail or download command:

```bash
octo-cli marketplace plugin list --scene-code default --plugin-type skill
octo-cli marketplace plugin get --plugin-id 'PLUGIN_ID'
octo-cli marketplace plugin download --plugin-id 'PLUGIN_ID' --output ./skill.zip
octo-cli marketplace plugin list --scene-code default --plugin-type connector
```

The old `marketplace skill list`, `marketplace skill download`, and
`marketplace mcp list` commands are retired on this client. Catalog listing needs
`--scene-code` and normally `--plugin-type`; the owned all-types view can use
`--scene-code default --mode mine`. Lists are paginated, so one page is not a
complete catalog or ownership check.

The CLI uses its active credential and Space context. For a `bf_` User Bot, the
service resolves the owner's identity and the Bot's authoritative Space. Supplying
a different Space header does not grant cross-Space access, and the Bot does not
inherit its owner's Space administration role.

Downloading does not install or execute the Skill. The installer must inspect the
archive, reject unsafe paths and links, preserve any existing installation, and use
the runtime's reload flow. Never execute archive scripts as part of extraction.
Do not expect the retired download response's hash fields from the ZIP endpoint.
