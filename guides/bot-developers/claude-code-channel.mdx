**[`cc-channel-octo`](https://github.com/Mininglamp-OSS/cc-channel-octo)** bridges
[Claude Code](https://docs.anthropic.com/en/docs/claude-code) into Octo IM via the Claude Agent
SDK. It's the most mature channel — prebuilt npm binary, real-time per-chunk streaming, agent
skills, and scheduled tasks.

<Note>
  The end-to-end first run is covered in
  [Connect your first agent](/get-started/quickstart-connect-a-bot). This page is the reference
  for its features and configuration.
</Note>

## Run it

```bash
npm install -g @mininglamp-oss/cc-channel-octo@1.0.3
cc-channel-octo        # after writing the config files below
```

Requires Node ≥ 22, an Octo Assistant token (`bf_…`), the Claude Code CLI
(`npm i -g @anthropic-ai/claude-code`), and `ANTHROPIC_API_KEY`.

## Configuration layout

Everything lives under `~/.cc-channel-octo/`:

```text
~/.cc-channel-octo/
├── config.json          GLOBAL: shared defaults + the list of bots (no token)
├── skills/              optional: skills shared by ALL bots
└── <botId>/             one self-contained subtree per bot ("default" for one bot)
    ├── config.json      THIS bot: botToken (required) + per-bot overrides
    ├── SOUL.md          optional personality (overrides sdk.systemPrompt)
    ├── skills/          optional: skills for THIS bot
    ├── data/            SQLite history
    ├── workspace/       per-session working directories
    └── memory/          long-term auto-memory
```

Gateway config is **JSON files only** — there are no environment-variable overrides.
The gateway derives its managed `data`/`workspace`/`memory` paths from `<baseDir>/<id>/…`.
This directory layout organizes the gateway's files; it does not confine Agent tools to that subtree.

## Features

<CardGroup cols={2}>
  <Card title="Streaming output" icon="bolt">
    Real-time delivery via Octo's stream API with 800 ms throttled flushes, typing indicators,
    and automatic fallback to plain messages.
  </Card>
  <Card title="Tool progress" icon="wrench">
    Opt-in `🔧 Running <tool>(…)` notices as the agent invokes tools, deduped and capped per turn.
  </Card>
  <Card title="Group awareness" icon="users">
    Responds only to @mentions in groups; injects recent group context so Claude follows the
    discussion.
  </Card>
  <Card title="Session persistence" icon="database">
    SQLite-backed history (40-message sliding window) with 7-day expiry.
  </Card>

In-chat commands: `/reset` (clear your session), `/config` (show settings), `/help`. A per-session
token bucket rate-limits requests (default 5/min).

## Security model

This page targets the published [v1.0.3](https://github.com/Mininglamp-OSS/cc-channel-octo/releases/tag/v1.0.3),
verified at [`1340db74ab54`](https://github.com/Mininglamp-OSS/cc-channel-octo/blob/1340db74ab549230ce8a0b480159b6ef9a2c5987/src/config.ts).

<Warning>
  The default configuration uses `sdk.allowedTools: "*"` and
  `sdk.permissionMode: "bypassPermissions"`. The bridge also passes
  `allowDangerouslySkipPermissions: true` to the Claude Agent SDK. Do not expect a human
  permission prompt before tools run. Review these defaults before connecting the Bot.
</Warning>

For `"*"`, the bridge omits the SDK's `allowedTools` option, leaving SDK tool selection at
its default. An explicit tool-name array is forwarded; it does not automatically change
`permissionMode`. Check the selected SDK's permission behavior before relying on a tool list
as an access restriction. See the [released option forwarding](https://github.com/Mininglamp-OSS/cc-channel-octo/blob/1340db74ab549230ce8a0b480159b6ef9a2c5987/src/agent-bridge.ts).

Each session gets a derived working directory. That `cwd` is a starting directory, not an
OS filesystem or network sandbox. It does not prevent tools from using absolute paths or
other resources available to the gateway's OS account. System-prompt safety instructions
also do not impose OS access controls. Run the gateway with only the files, credentials,
and network access you intend to delegate; use OS-level isolation where you need that boundary.
See the [released working-directory implementation](https://github.com/Mininglamp-OSS/cc-channel-octo/blob/1340db74ab549230ce8a0b480159b6ef9a2c5987/src/cwd-resolver.ts).

## Multi-Assistant & scheduled tasks

List several Assistants under the global `bots[]` (each with its own `<id>/config.json`) to run many
in one process. Scheduled tasks let an Assistant run on a cron-like trigger. See the repo README for
the full field reference.
