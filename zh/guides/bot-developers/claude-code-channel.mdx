**[`cc-channel-octo`](https://github.com/Mininglamp-OSS/cc-channel-octo)** 通过 Claude Agent
SDK 把 [Claude Code](https://docs.anthropic.com/en/docs/claude-code) 桥接进 Octo IM。它是最成熟的
频道——预构建的 npm 二进制、实时逐块流式、智能体
技能，以及定时任务。

<Note>
  端到端的首次运行已在
  [连接你的第一个智能体](/zh/get-started/quickstart-connect-a-bot)中介绍。本页是
  其功能与配置的参考。
</Note>

## 运行它

```bash
npm install -g @mininglamp-oss/cc-channel-octo@1.0.3
cc-channel-octo        # after writing the config files below
```

需要 Node ≥ 22、一个 Octo 助理令牌（`bf_…`）、Claude Code CLI
（`npm i -g @anthropic-ai/claude-code`），以及 `ANTHROPIC_API_KEY`。

## 配置布局

一切都位于 `~/.cc-channel-octo/` 之下：

```text
~/.cc-channel-octo/
├── config.json          GLOBAL: shared defaults + the list of bots (no token)
├── skills/              optional: skills shared by ALL bots
└── <botId>/             one self-contained subtree per bot ("default" for one bot)
    ├── config.json      THIS bot: botToken (required) + per-bot overrides
    ├── SOUL.md          optional personality (overrides sdk.systemPrompt)
    ├── skills/          optional: skills for THIS bot
    ├── data/            SQLite history
    ├── workspace/       per-session working directories
    └── memory/          long-term auto-memory
```

网关配置**仅为 JSON 文件**——没有环境变量覆盖机制。网关从 `<baseDir>/<id>/…` 派生
自己管理的 `data`/`workspace`/`memory` 路径。这种目录布局用于组织网关文件，
不会把智能体工具的访问范围限制在该子树内。

## 功能

<CardGroup cols={2}>
  <Card title="流式输出" icon="bolt">
    通过 Octo 的 stream API 实时投递，带 800 ms 节流刷新、正在输入指示，
    并在必要时自动回退到普通消息。
  </Card>
  <Card title="工具进度" icon="wrench">
    可选启用的 `🔧 Running <tool>(…)` 提示，在智能体调用工具时显示，按回合去重并设上限。
  </Card>
  <Card title="群组感知" icon="users">
    在群组中仅响应 @提及；注入最近的群组上下文，以便 Claude 跟上
    讨论。
  </Card>
  <Card title="会话持久化" icon="database">
    由 SQLite 支撑的历史记录（40 条消息的滑动窗口），有 7 天过期期限。
  </Card>
</CardGroup>

聊天内命令：`/reset`（清除你的会话）、`/config`（显示设置）、`/help`。一个逐会话的
令牌桶对请求进行限流（默认 5/min）。

## 安全模型

本页针对已发布的 [v1.0.3](https://github.com/Mininglamp-OSS/cc-channel-octo/releases/tag/v1.0.3)，
核实源码为 [`1340db74ab54`](https://github.com/Mininglamp-OSS/cc-channel-octo/blob/1340db74ab549230ce8a0b480159b6ef9a2c5987/src/config.ts)。

<Warning>
  默认配置为 `sdk.allowedTools: "*"` 和 `sdk.permissionMode: "bypassPermissions"`；
  桥接层还会向 Claude Agent SDK 传入 `allowDangerouslySkipPermissions: true`。
  不要预期工具执行前会等待人工权限确认。连接 Bot 前，请先检查这些默认值。
</Warning>

当值为 `"*"` 时，桥接层省略 SDK 的 `allowedTools` 选项，由 SDK 使用默认工具选择。
显式工具名数组会直接转发，但不会自动改变 `permissionMode`。
将工具列表当作访问限制前，先核对所选 SDK 的权限行为。
参见[发行版选项转发实现](https://github.com/Mininglamp-OSS/cc-channel-octo/blob/1340db74ab549230ce8a0b480159b6ef9a2c5987/src/agent-bridge.ts)。

每个会话获得一个派生工作目录。`cwd` 是起始目录，不是操作系统级文件系统或网络沙箱；
它不会阻止工具使用绝对路径，或访问网关操作系统账号可用的其他资源。
系统提示词中的安全指令也不会施加操作系统访问控制。
运行网关时，只提供你打算交给它的文件、凭据与网络访问权限；
需要该安全边界时，使用操作系统级隔离。
参见[发行版工作目录实现](https://github.com/Mininglamp-OSS/cc-channel-octo/blob/1340db74ab549230ce8a0b480159b6ef9a2c5987/src/cwd-resolver.ts)。

## 多助理与定时任务

在全局的 `bots[]` 下列出多个助理（每个都有自己的 `<id>/config.json`），即可在一个进程中运行多个。
定时任务让助理可以按类 cron 的触发器运行。完整的字段参考请见仓库 README。
