## Octo Runtime——本地执行 SDK

正式发布的 [Runtime v1.1.3](https://github.com/Mininglamp-OSS/octo-runtime/releases/tag/v1.1.3)
要求 **Node.js 24.x 或 26.x**。安装固定版本：

```bash
npm install @mininglamp-oss/octo-runtime@1.1.3
```

| 公共入口 | v1.1.3 用途 |
|---|---|
| `@mininglamp-oss/octo-runtime/host` | 用 `createKernelService` / `createExtraService` 原生构建 Kernel 与 Extra 服务，由宿主拥有生命周期。 |
| `@mininglamp-oss/octo-runtime/executor-kernel` | 用 `KernelClient.invoke` 在 Kernel 监督的 worker 中执行。 |
| `@mininglamp-oss/octo-runtime/extras/channel-gateway` | Gateway 配置、类型及宿主注入的 `createSessionStore` 合同。 |

桌面或自研应用应嵌入 SDK。宿主原生 import 所选 Extra 模块并传给 `createExtraService`，
在调用进程中构造 Kernel 和 Extra 服务；宿主自有 worker 入口 import 所选 Adapter，再调用 `serveWorker`。
SDK 装配不要求、读取或生成永久 / 临时 manifest，也不通过外部 Node / CLI 代启顶层服务。
标准 CLI 包的完整模块目录不等于每个 SDK 产品都隐式依赖全部模块。
参见[发行版原生 SDK 与模块载入合同](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/docs/zh-CN/concepts/module-loading.md)。智能体执行仍使用隔离 worker。
Gateway 默认为 `MemoryImSessionStore`；持久会话存储由宿主负责，不提供内建 SQLite 后端。

<Warning>
  对 `KernelClient.invoke` 的迭代执行 break 或关闭 client，只会停止观察，不会取消执行。
  通过 `AbortSignal` 或 `cancelInvocation` 请求取消，再读取最终结果；取消请求被接受不代表清理已完成。
</Warning>

v1.1.3 的 Context 固定标记使用英文 XML 注释；字面标签 `<guidence>` 保留传入 Markdown 与换行，
API 字段仍为 `guidance`。`<data>` 用 CDATA 包裹 JSON，并拆分内容中的 `]]>` 终止符。
业务内容保留原文。这些标记只是格式，不构成授权或信任边界。参见[发行版 Context 渲染实现](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/packages/octo-runtime-executor-core/src/model-input.ts)。

Context JSON 校验检查结构，不验证作者身份或权限。可信宿主必须显式解析配置层；
`KernelClient` 不会自动加载 `defaults` / `mandatory`。使用配置解析时，将会话指令放入可信的
`mandatory` 配置。本地 IPC 信任同一操作系统账号的客户端；业务调用者认证与资源授权仍由宿主负责。

此版本也包含 `grok-build` Adapter。上游真实 harness 验证仅覆盖 macOS arm64、
Grok Build 1.0.67、文本流与显式跨 CLI 进程续聊；不能据此认定原生工具、审批 / 追问 / 计划审核、
MCP、图片或其他平台已经实测。认证由宿主 / harness 负责。
采用前请核对[固定版 Adapter 合同及验证限制](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/packages/octo-runtime-adapter-grok-build/README.md)；
源码 / fixture 覆盖不等于生产 Provider 或 IM 实际可用。

以上合同核实于 [`fe19d3504315`](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/README.md)：
[原生服务入口](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/public/host.ts)、
[执行与取消](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/docs/zh-CN/reference/output-and-control.md)、
[宿主会话存储](https://github.com/Mininglamp-OSS/octo-runtime/blob/fe19d350431534da4ed3a76f3466add4ced86d81/SDK_CHANNEL_GATEWAY_GUIDE.md)与

## octo-auth——凭据校验器

**[`octo-auth`](https://github.com/Mininglamp-OSS/octo-auth)** 在单一 `Verifier` 接口之后校验 Octo 凭据（会话、`bf_` 机器人令牌、`uk_` 用户密钥），并支持可插拔的缓存与指标。它以 **Go 和 TypeScript** 两种形态发布，以在各服务间保持一致。

```bash
go get github.com/Mininglamp-OSS/octo-auth/go       # Go 1.25+
```

<Note>
  TypeScript 包 `@mininglamp-oss/octo-auth`(Node ≥ 20,纯 ESM)**尚未发布到 npm** ——
  在发布之前请从仓库安装(`npm install "git+https://github.com/Mininglamp-OSS/octo-auth.git#main:ts"`)。
</Note>

- **领域**——`sessionVerifier`、`botTokenVerifier`、`userKeyVerifier`，外加一个按凭据前缀分派的 `MultiVerifier`。
- **中间件**——Go：`net/http`、`gin`、`echo`、`wkhttp`；TS：`express`、`@hocuspocus/server`。
- 默认提供**故障即关闭**的类型化错误与反枚举。

传输层契约位于 `octo-auth/contract/*.yaml`，也是自动生成的[鉴权校验 API](/zh/reference/auth-verify-api) 与[错误参考](/zh/reference/errors-and-envelopes)的来源。

## octo-lib——共享 Go 库

**[`octo-lib`](https://github.com/Mininglamp-OSS/octo-lib)** 是跨各服务使用的共享核心 Go 库——协议类型、加密、存储与 HTTP 辅助工具。值得注意的是，它拥有 `contract/searchmsg` 消息契约，[搜索流水线](/zh/concepts/search-and-export-pipeline)的生产者与索引器都依赖于它。适配器与服务都会 import 它，使横切的基础原语保持一致（且精简）。

```bash
go get github.com/Mininglamp-OSS/octo-lib
```

<Note>
  对于 REST API 与 CLI，请使用[自动生成的参考](/zh/reference/rest-websocket-api)——这些界面由内嵌的 OpenAPI 规范驱动，而非某个独立的 SDK。
</Note>
