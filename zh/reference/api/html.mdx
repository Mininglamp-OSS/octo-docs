### Create an HTML document or publish a later version

`POST /docs-html/v1/docs` · CLI 命令: `html.publish` · 🟠 写

Create by omitting slug; the CLI generates a fresh idempotency_key unless one is supplied explicitly. Every new document receives a canonical doc_id whether mounted or unmounted; response data.slug is the document reference and equals data.doc_id. To publish a later version, first run html source &lt;doc-ref&gt; and retain data.html with data.version, edit that source, then pass the previously returned data.slug, set version to the source version plus one, and omit idempotency_key. On version_conflict or version_required, the bot must autonomously reread the latest source, reapply only the intended changes while preserving other edits, and republish to the same slug within the same task, up to three recovery attempts; do not end the task by forwarding a routine version error to the user. Never only increase version and resend stale HTML. Pass only a slug the server returned earlier: an unregistered slug does not create a canonical document, it produces a legacy unregistered one that never appears in the file list. Old legacy documents continue to use their legacy slug as that reference. A display name is metadata, not identity: publishing the same name without the saved reference creates a different document, so same-name republish is not supported. Do not infer identity mode from mount_type or from whether doc_id is non-empty. Requires the write token (Bearer). The server stamps commentable artifacts and reconciles existing comment anchors.

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `slug` | string |  | Legacy wire name for an existing document reference. Omit when creating. For every later publish pass the prior response data.slug: it is the canonical doc_id for a new document or the legacy slug for an old document. Never pass a display name as identity. |
| `html` | string | ✓ | the full self-contained HTML document body |
| `idempotency_key` | string |  | Optional caller key for retrying this exact creation operation; otherwise the CLI generates a cryptographically random key once per invocation and reuses it for transport retries. Omit when republishing an existing slug. |
| `version` | integer |  | New output version: for updates send the source version read before editing plus one. On servers with octo-docs-html#34 deployed, the server requires current latest+1 for bot updates (428 version_required if missing/zero, 409 version_conflict if mismatched). The HTML backend will be deployed and verified on every serving instance before this CLI workflow is released. Omit for first publication. Do not increase this value without rereading and editing the latest source. |
| `meta` | object |  | optional metadata (e.g. &#123;"title":"..."&#125;) |
| `mount_type` | enum(`group`, `space`, `thread`) |  | Optional placement in docs-backend and the file sidebar; 'group', 'space', and 'thread' are supported. Mounting does not determine document identity. |
| `group_no` | string |  | group number; supply when mount_type=group |
| `thread_id` | string |  | thread id; supply when mount_type=thread |

### Delete a document (forbidden for bots, including author/owner/admin)

`DELETE /docs-html/v1/docs/{doc_id}` · CLI 命令: `html.rm` · 🟠 写

Bots must not invoke this operation, even for documents they authored, own, or administer. Ask a human with document admin permission to delete it in Octo; do not use docs.delete or raw API calls as a workaround. This command targets the HTML service, not the docs-backend bot deletion route, so enforcement must be verified for that service separately. If bot_delete_forbidden is returned, stop without retrying or changing identity/Space. Publishing and editing remain governed by their existing permissions.

</Warning>
